# Daoji

> 本文档为非权威的简体中文翻译。请参阅[英文原文](../../../README.md)；如有语义冲突，以英文原文为准。

**由明确的工程文档控制的软件开发。**

本仓库定义了 Daoji，它是一款通过明确、版本化且可验证的工程文档来协调 AI
智能体的工具。这些文档使项目决策能够持久保存并接受评审。项目将这些决策存储在
临时提示词之外。

*Daoji* 这一名称源自《道德经》[第十四章](https://ctext.org/dao-de-jing/zh#n11605)
中的中文词语“道纪”（繁体：道紀；拼音：*dào jì*）：“执古之道，以御今之有。
能知古始，是谓道纪。”在本项目中，*Daoji* 指将决策起源与当前工作联系起来的
指导秩序和可追溯脉络。

Daoji 并非旨在取代生成代码的 AI 智能体，而是旨在提供控制其工作的设计、约束、
工作顺序和验收标准。

## 开发模型

开发过程包含以下阶段：

1. 意图
2. 需求
3. 设计
4. 工程政策
5. 实施计划
6. 验证计划
7. AI 生成的代码
8. 实施记录
9. 构建与验证
10. 验证记录
11. 变更摘要
12. 可运行的软件

工程资产是项目创建或维护的文档、软件项或记录。

每个阶段都会产出由项目存储在版本控制中的工程资产。每项后续资产都必须链接到
授权该资产的决策以及适用于该资产的约束。验证证据必须表明实施是否满足这些约束。

提示词或议题会启动此过程，但其本身不会成为权威决策。项目首先将请求转化为已接受
的意图和需求。记录在案的设计评估会确定该变更是需要单独的设计文档，还是可以在
实施计划中保留一份简短的设计记录。在实施之前，项目还会检查适用的工程政策、识别
缺失的政策并创建验证计划。实施任务会链接到其范围所需的具体参考资料。静态检查、
测试和评审会生成带有明确测试结论的验证记录。
[Daoji 开发生命周期标准](standards/DEVELOPMENT_LIFECYCLE_STANDARD.md)定义了完整过程以及
每个阶段的退出条件。

## 核心论点

AI 智能体可以实施范围有限的任务，但无法长期可靠地保留项目上下文。大型软件系统
需要权威的项目记录。当信息来源存在分歧时，此记录会控制决策。人必须能够阅读此
记录，智能体必须能够解释此记录，工具必须能够检查此记录。软件发生变更时，项目
必须更新此记录。

Daoji 使用仓库作为其权威项目记录。Daoji 旨在提供以下能力：

- 捕获意图并将其转化为可评审的需求。
- 记录从需求到设计、计划、代码和测试的链接。
- 在代码生成之前和期间应用项目特定的工程政策。
- 将具有明确范围的工作分配给一个或多个 AI 智能体。
- 在实施之前定义项目如何测试和验证每项变更。
- 记录项目如何实施每项变更。
- 收集构建和验证证据。
- 创建适合直接用作拉取请求说明的变更摘要。
- 检测已记录决策与运行中软件之间的不一致。
- 要求变更不仅更新代码，还要更新相关文档。

## 当前状态

Daoji 正在开始实施 Level 1。本仓库包含一个最小 Rust 命令行脚手架，以及允许并
约束该脚手架的权威文档。首个具有实际功能的文档验证器仍属于后续工作。

[Daoji 项目章程](PROJECT_CHARTER.md)包含初始项目需求和最高优先级规则。
[文档标准](standards/DOCUMENTATION_STANDARD.md)定义项目文档的结构、长度限制、链接、索引和
评审方式。
[开发生命周期标准](standards/DEVELOPMENT_LIFECYCLE_STANDARD.md)定义了项目如何将这些规则
应用于软件变更。

初始核心模型、验证、协调和命令行界面使用 Rust。项目尚未选择用于未规定未来组件的
架构或工具链。参见[初始 Rust 架构决策](../../design/0001-initial-rust-architecture.md)。

## Daoji 自我开发目标

Daoji 应该逐步使用自身工作流来规划、实施和验证对 Daoji 的变更。初始文档定义
第一个可执行版本。该版本验证并协调后续变更。只有当工作流要求由人员进行评审，并
记录每项决策以便人员日后审计时，项目才能实现这一目标。

## 路线图

本路线图是资料性内容，用于记录预期交付顺序。它不会取代已验收的需求、设计、政策
或计划。实施每个条目前，项目都必须使其进入 [Daoji 开发生命周期](standards/DEVELOPMENT_LIFECYCLE_STANDARD.md)。
如果早期条目产生的证据改变了后续条目的需求或设计，项目可以修订后续条目。

- [ ] **构建权威项目记录核心。** 定义工程资产模式、标识符、生命周期状态、带类型的
  链接、优先级规则和证据模型。对文档结构、元数据、链接、状态转换、政策规则和
  可追溯性实施确定性校验。完成标准是后续 Daoji 变更能够将此校验器作为质量门禁。
- [ ] **在本地 TUI 中完成文档生命周期。** 为项目内嵌文档构建文本用户界面（TUI）。
  提供聚焦编辑、文档图导航、校验反馈、状态视图、人员批准关卡和中断后的工作恢复。
  引导一项变更从意图推进到已验收的实施与验证计划，再生成实施记录、验证记录和最终
  变更摘要。此阶段负责准备和评审工作，尚不自动调用智能体。完成标准是 Daoji 能通过
  TUI 定义自身的下一项可执行变更。
- [ ] **将外部项目文档接入 TUI。** 为外部议题、规格、决策记录和证据增加明确的
  适配器。保留来源身份和修订信息，显示同步与冲突状态，并要求人员解决权威性冲突。
  除非已验收的设计和政策将外部来源纳入权威项目记录，否则它们仍只是输入或导航辅助。
  完成标准是外部请求能够进入本地生命周期，且不会丢失来源信息或批准过程。
- [ ] **协调智能体工作并实现常规自开发。** 将已验收计划转换为不依赖供应商、范围明确
  的智能体任务，并提供最低限度的充分上下文、权限、约束、输出和完成标准。为能力发现、
  调用、上下文传递、权限映射、事件、取消、恢复和标准化工作结果定义统一的智能体适配
  协议。增加工具与进程隔离、单智能体与多智能体协调、验证执行、证据留存和未完成工作
  的恢复机制。在重要决策点保留人员批准，并要求独立验证 Daoji。完成标准是 Daoji 的
  常规变更从意图到可审计的变更摘要均使用 Daoji。
- [ ] **接入 `pi` 智能体。** 将 `pi` 的能力、会话、权限、工具事件、取消、错误和工作
  结果映射到 Daoji 适配协议。使用具有代表性的范围明确任务增加一致性测试和端到端测试。
  完成标准是 Daoji 能够通过 `pi` 执行并审计一项已验收任务。
- [ ] **接入 Claude Code。** 将 Claude Code 的身份验证、能力、会话、权限、工具事件、
  取消、错误和工作结果映射到 Daoji 适配协议。使用具有代表性的范围明确任务增加一致性
  测试和端到端测试。完成标准是 Daoji 能够通过 Claude Code 执行并审计一项已验收任务。
- [ ] **接入 Codex CLI。** 将 Codex CLI 的身份验证、能力、会话、权限、工具事件、取消、
  错误和工作结果映射到 Daoji 适配协议。使用具有代表性的范围明确任务增加一致性测试和
  端到端测试。完成标准是 Daoji 能够通过 Codex CLI 执行并审计一项已验收任务。
- [ ] **接入 Kimi Code。** 将 Kimi Code 的身份验证、能力、会话、权限、工具事件、取消、
  错误和工作结果映射到 Daoji 适配协议。使用具有代表性的范围明确任务增加一致性测试和
  端到端测试。完成标准是 Daoji 能够通过 Kimi Code 执行并审计一项已验收任务。
- [ ] **Web 开发环境：支持受控的远程开发。** 通过 Web 界面公开相同的文档图和生命
  周期引擎。增加经过身份验证的项目、隔离的远程工作区、可恢复会话、评审与批准流程、
  流式任务和验证结果、审计记录以及受控的机密信息访问。在实施前定义租户隔离、隐私、
  保留、可靠性、部署和运维政策。
- [ ] **macOS 原生客户端：提供一体化桌面工作流。** 复用已验收的核心格式和协议。
  增加原生项目与文档导航、本地工作区与钥匙串集成、通知、无障碍、离线运行、签名
  分发、更新和恢复。仅在 macOS 需求和利弊获得验收后选择 UI 架构。
- [ ] **Linux 原生客户端：提供可跨发行版交付的桌面工作流。** 复用相同的已验收核心
  格式和协议，同时针对选定 Linux 环境定义桌面集成、凭据存储、沙箱、打包、更新、
  无障碍和支持边界。仅在支持环境和发布政策获得验收后选择工具包与软件包格式。

## 文档地图

[Daoji 文档地图](DOCUMENT_MAP.md)是面向人员和智能体的主要文档入口。它标明治理文档、
设计、工程政策、变更记录、参考资料和译文，并区分各文档的权威性。

开始工作时：

- 查阅[项目章程](PROJECT_CHARTER.md)，了解项目目的、范围、优先级和最高层规则。
- 查阅[开发生命周期标准](standards/DEVELOPMENT_LIFECYCLE_STANDARD.md)，规划、实施或验证

- 查阅[文档标准](standards/DOCUMENTATION_STANDARD.md)，创建、评审或维护项目文档。
- 查阅[完整文档地图](DOCUMENT_MAP.md)，定位设计、工程政策、变更记录和其他项目资料。

## 开发

安装 `rust-toolchain.toml` 声明的工具链。按照从窄到宽的顺序运行本地质量检查：

```text
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-targets --all-features --locked
cargo doc --workspace --all-features --no-deps
cargo build --workspace --all-features --locked --release
```

CI 还会强制检查行覆盖率、依赖项公告、许可证、来源和跨平台测试。命令和阈值由
[Rust 工程政策](../../policies/RUST_ENGINEERING_POLICY.md)控制。
