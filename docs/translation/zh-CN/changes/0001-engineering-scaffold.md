# 工程脚手架变更

> 本文档是非权威的简体中文翻译。请参阅[英文原文](../../../changes/0001-engineering-scaffold.md)；如有语义冲突，以英文原文为准。

文档类型：合并的变更条目、意图、需求、实施计划、验证计划、实施记录、验证记录和
变更摘要

决策负责人：项目所有者

## 来源请求

2026-08-02，项目所有者要求根据项目章程、同类规范与智能体执行框架项目，以及
AI 驱动开发对严格自动化测试和代码检查的需要，创建工程脚手架。在设计评审期间，
所有者批准 Rust 用于初始实施，并将所有额外工具链和接口决策推迟到未来的已验收
需求。

## 意图

创建最小的实用工程基础，使未来 AI 生成的 Rust 变更可以接受机械检查。脚手架影响
项目维护者和实施智能体。成功意味着全新检出的仓库可以使用确定性命令对占位命令行
进程执行格式化、代码检查、测试、文档构建、审计和构建，并采用严格的 CI 门禁。

本变更不实施文档验证、智能体协调、用户界面、其它工具链、发布、安装、遥测或发行。

## 需求

### ES-001：可复现的 Rust 脚手架

仓库必须包含一个最小 Rust 2024 命令行软件包，该软件包可以使用声明的最低工具链
和已提交的依赖锁文件构建。运行占位二进制文件必须成功终止，且不产生输出或副作用。

验收标准：`cargo build --locked --release` 成功，且集成测试验证进程成功终止。

### ES-002：严格静态检查

脚手架必须拒绝格式差异、编译器警告、Clippy 警告、不安全代码、缺少文档的公共项，
以及生产代码中的 `unwrap`、`expect`、panic、`todo!` 或 `unimplemented!`。

验收标准：VP-001 和 VP-002 中的格式化及 Clippy 命令成功，并将警告视为错误。

### ES-003：自动化测试和覆盖率

脚手架必须在 Linux、macOS 和 Windows 上运行确定性测试。初始可执行代码行必须达到
100% 行覆盖率。

验收标准：VP-003 和 VP-005 通过，且 CI 定义三个平台的测试矩阵。

### ES-004：供应链控制

脚手架必须锁定依赖项、审计公告、限制许可证和来源、拒绝重复依赖与通配符依赖、
固定 CI action，并配置自动更新提案。

验收标准：VP-006 通过，且仓库评审确认使用完整 action 提交哈希和 Dependabot
配置。

### ES-005：推迟工具链决策

已验收架构必须将初始核心行为分配给 Rust，同时不为尚未规定的未来组件选择语言、
框架、运行时或构建系统。

验收标准：架构决策记录当前范围、取舍和否决的替代方案；本变更不创建额外工具链
资产。

## 设计评估

本变更选择基础技术、建立后续变更模式并影响未来运行时架构，因此必须有单独设计。
已验收的[初始 Rust 架构](../design/0001-initial-rust-architecture.md)处理 ES-001 和
ES-005。它使用一个无依赖二进制 crate，并推迟尚未规定未来组件的所有架构决策。

## 政策适用性和完整性

已验收的 [Rust 工程政策](../policies/RUST_ENGINEERING_POLICY.md)控制编码、静态分析、
依赖项、测试、接口、供应链安全和生成资产。文档标准控制所有变更的文档。

安全适用于依赖项和 CI 完整性；可执行文件不访问数据、网络、文件系统、机密信息或
子进程。隐私、数据处理、可靠性、性能、可观测性、无障碍性、国际化、迁移、部署、
运维和发布不适用于这个无功能占位程序。这些类别需要新政策或修订政策，才能开始
依赖它们的实施。本变更没有已批准例外。

## 验证计划

检查按照从快且窄到慢且宽的顺序运行。输入是干净的仓库和锁定的依赖项。每条命令的
预期结果都是退出状态 0。除了检索依赖项和公告外，检查不需要机密信息、测试数据、
重试、清理或外部服务。

| ID | 需求 | 方法和命令 | 环境 |
| --- | --- | --- | --- |
| VP-001 | ES-002 | `cargo fmt --all --check` | 本地和 Linux CI |
| VP-002 | ES-002 | `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings` | 本地和 Linux CI |
| VP-003 | ES-001、ES-003 | `cargo test --workspace --all-targets --all-features --locked` | 本地和 Linux、macOS、Windows CI |
| VP-004 | ES-002 | `cargo doc --workspace --all-features --no-deps` | 本地和 Linux CI |
| VP-005 | ES-003 | `cargo llvm-cov --workspace --all-features --locked --fail-under-lines 100` | Linux CI |
| VP-006 | ES-004 | `cargo audit --deny warnings` 和 `cargo deny check` | Linux CI |
| VP-007 | ES-001 | `cargo build --workspace --all-features --locked --release` | 本地和 Linux CI |

由于 Daoji 尚未实施 Level 1 验证，文档和元数据验证由人员完成。评审检查元数据、
链接、需求标识符和一致性。占位程序没有对应边界或行为，因此省略集成、系统、迁移、
性能和可靠性测试。源代码托管提供商保留托管 CI 日志；本记录保留可复现的命令和结论。

## 变更摘要

### 目的

为未来 AI 生成的 Daoji 实施工作建立严格且可复现的工程脚手架。

### 相关需求

本变更条目中的 ES-001 至 ES-005；初始 Rust 架构；Rust 工程政策；AT-001 至
AT-003；VP-001 至 VP-007。

### 变更

- 添加无依赖 Rust 2024 命令行脚手架和集成测试。
- 添加严格的格式化、Clippy、文档、测试、覆盖率、构建、公告、许可证、来源和依赖
  门禁。
- 添加使用不可变 action 引用的三平台 CI 和自动更新提案。
- 记录已验收的初始 Rust 架构和推迟的工具链范围。

### 实施说明

项目有意不决定额外工具链和尚未规定的接口架构。实施没有偏离计划。

### 验证

请参阅本文档中的验证记录。合并前必须完成本地和托管结果。

### 风险和兼容性

Rust 增加全新构建时间和贡献者学习成本。占位程序不引入用户可见行为、持久化、
网络访问、部署或兼容性承诺。

### 文档

本变更更新 README 和文档地图，并添加架构、政策和生命周期记录。

### 未解决工作

实施 Level 1 验证或添加其它工具链都需要单独的已验收变更。托管 CI 证据仍待生成。
